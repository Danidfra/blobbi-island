## Architecture

```
MovableBlobbi (local input + movement controller)
└── BlobbiActor (shared ground-anchor primitive)
    ├── anchor: left/top = GROUND point, translate(-50%, -100%)
    ├── scale rig: scale(depth × seat), transform-origin: bottom center
    │   └── float wrapper → CurrentBlobbiDisplay (local wrapper → pure renderer)
    ├── shadow: centered ON the ground point, width scales with depth,
    │           outside the float wrapper
    ├── labelSlot (remote name labels)
    └── dev-only debug markers (crosshair/box/readout via DebugOverlaysContext)

RemoteBlobbiSprite (presence interpolation adapter)
└── BlobbiActor → BlobbiRendererView (pure)
```

`BlobbiActor` owns geometry only — no input capture, movement state, presence,
boundary selection, or publishing. Local and remote actors produce identical
anchor/scale/shadow/pose geometry for the same inputs.

## Conversion formulas (src/lib/blobbi-ground.ts)

- `halfH(size, scale) = BLOBBI_RENDER_SIZE_PX[size]/2 × scale × 100 / 697`
- `centerToGround(p) = { x, y: y + halfH }`; `groundToCenter` inverse.
- `worldDistancePx(a, b) = hypot(Δx% × 1046/100, Δy% × 697/100)` — the shared
  ISOTROPIC arrival metric. Thresholds: `ARRIVAL_THRESHOLD_PX = 40`
  (touch 64; below the 48 px theater seat half-pitch), movement snap 2 px.
- `actorVisualFocusPoint(ground, size, scale)` — gaze targets aim at body
  centers derived from ground anchors; vectors never mix conventions.

## Config migration formula

Every center-era y (boundaries, spawns, exits, walk targets, z-bands) moved
down by `halfH(roomSize, scale(y))`, with `scale(y)` sampled on the room's
depth ramp over the OLD boundary extent — preserving the previous ON-SCREEN
walkable floor and stop points exactly. Z-band thresholds (measured from the
bottom) moved UP by the same amount. Generated by
`scratchpad/migrate_ground.py` (session scratch; formula documented here).

Pose anchors are explicit exceptions reached via boundary-bypassing
`goTo(..., immediate)`:
- Theater seats (hardening pass): the pose is a VISUAL POSE ANCHOR calibrated
  to the cushion — `seatAnchorPosition = cushion line + SEAT_CONTACT_RATIO
  (0.3) × (128 × seatedScale / 697)`, so the lower body tucks into the seat
  and rows sink proportionally to their scale. (A full half-body buried the
  sitter; zero offset floated it — both were real regressions.) The walk
  APPROACH is separate: `SEAT_APPROACH_TARGET` (floor at the seat's front
  base, `seatApproachPosition`). Seated z comes from the seat ROW
  (`chair z − 5`, floor 9) via `resolveSeatedRender`, never from the standing
  y-bands.
- Bed: `getBedSleepPose = bed + 4.2%y`; the walk goes to
  `getBedWalkTarget` (pose clamped into the boundary), arrival uses the shared
  world-px threshold, then snaps to the pose.
- Shop/Nostr chairs have NO seated pose: the anchor fraction (yPercent 85 of
  the chair sprite, measured on the chair element itself, resolved against
  `[data-world-surface]`) is a standing/pseudo-sit approach; the modal fires
  as before.
- Arcade machines: the RUNTIME live-rect target (`computeMachineTarget`) and
  the DOM-free `machineAnchorPosition` share `arcadeMachineGroundOffsetPercent`
  (depth-scaled half body per floor), applied exactly once — the hardening
  pass fixed the runtime path, which had been left unconverted (Blobbis ended
  up inside cabinets/tables, reading as "stacked objects").

## Presence compatibility

Wire (kind 31950) keeps LEGACY CENTER semantics; no new fields. Conversion at
exactly two boundaries:
- out: `buildPresence31950` converts `anchor`/`goal` via `groundToWireCenter`;
- in: `processPresenceEvent` converts via `wireCenterToGround` (fixed-point
  iteration so the pair is exactly inverse even on steep ramps).

Also fixed at this boundary: heartbeats/sit/hide/activity now publish the LIVE
local position (`livePositionsRef[LOCAL_GAZE_KEY]`) instead of the walk
destination, and `posAt` measures distance in world px (matching its px/s
velocity) instead of percent.

## Debugging

- `/dev/rooms` (dev-only route): any room with real boundary/spawn/exit
  overlays and a login-free actor; debug overlays forced on; snap buttons
  drive `goTo(..., immediate)` so geometry is verifiable even where rAF is
  throttled (occluded automation windows).
- Debug overlays toggle: `BlobbiActor` draws the ground-point crosshair, box
  outline and a `g(x, y) ×scale z` readout.

## Known limitations / follow-ups

- The PhotoBooth modal still hosts its own `MovableBlobbi` in a modal-sized
  container (booth-local percent space; its boundary/spawn were migrated with
  the same formula).
- Remote accessories and remote sleep state remain unpublished (pre-existing).
- Depth scale still doesn't affect movement speed (unchanged by design; open
  question in the audit).
- Z-order against in-room objects was retuned numerically (same visual lines);
  full in-game visual confirmation of occlusion in arcade/town requires a
  logged-in session.
- The movement-start rAF loop previously only started via parent re-render
  side effects; `startAnimation()` now starts it explicitly (latent bug fixed).
